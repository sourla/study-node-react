## 과제 B. 버그 하나 고치기

### 증상

`/ssr`을 열면 화면은 멀쩡한데 콘솔에 에러가 하나 있다.

```
Hydration failed because the server rendered text didn't match the client.
+ 2026년 9월 1일
- Sep 1, 2026
```

### 원인

서버와 브라우저에서 **값이 달라지는 입력**이 렌더에 섞였다. 날짜 포맷(luxon `toLocaleString`)이 실행 환경의 로케일을 따르는데, 서버(Node)는 en-US, 브라우저는 ko-KR이라 같은 데이터로 다른 문자열이 나왔다. 라이브러리 자체가 아니라 "환경에 따라 달라지는 입력"이 문제다. 로케일·타임존, `Date.now()`, `Math.random()`, `window`/`localStorage` 분기가 같은 부류다.

### 시도 1 — hydration 전에는 목록을 안 그린다 (`debug/render-flow-answer`)

**방법.** `useSyncExternalStore`로 hydration 여부를 읽어(서버 스냅샷 `false`, 클라이언트 `true`) 서버 렌더와 hydration 중에는 fallback을, 그 뒤에 `PostList`를 그린다.

**결과.** 콘솔 에러는 사라졌다.

**비용 (curl로 실측).**

| 측정 (`curl -s localhost:5173/ssr`) | 수정 전 (`main`)                         | 시도 1                |
| ----------------------------------- | ---------------------------------------- | --------------------- |
| HTML에 게시글 제목 등장 횟수        | 2 (렌더된 목록 + 직렬화된 loader 데이터) | 1 (직렬화된 데이터만) |
| HTML에 날짜 문자열                  | `Sep 1, 2026`                            | 없음                  |
| HTML에 "불러오는 중"                | 없음                                     | 있음                  |

**해석.** 에러를 고친 게 아니라 **대조 자체를 피했다.** 목록이 클라이언트 전용이 되어 서버 HTML에서 사라졌다. 이제 `/ssr`이 `/csr`과 다른 점은 "데이터가 HTML에 실려 온다"뿐이고, SSR을 하는 이유를 목록 부분에서 포기한 셈이다.

**부작용 둘.**

- `HydrateFallback`은 React Router route module의 예약된 export 이름(clientLoader hydration 중 표시)이라, 다른 뜻의 컴포넌트에 이 이름을 쓰면 헷갈린다.
- `console.log`를 `useEffect` 밖으로 꺼내서 서버 렌더 중에도 실행된다. 서버 터미널에 `[page] SsrPage 진입`이 찍혔다(4회). "`[page]`는 브라우저"라는 접두어 약속이 깨진다.

**이 방법이 맞는 때.** 불일치가 불가피할 때. 화면 폭에 따른 레이아웃, 사용자의 로컬 시각처럼 서버가 알 수 없는 값을 보여 줘야 할 때 쓴다. 이번 버그는 입력을 고정하면 사라지는 종류라 해당하지 않는다.

### 시도 2 — 입력을 고정한다 (`debug/render-flow-answer-2`)

계획: 날짜 포맷의 로케일(그리고 타임존)을 서버와 브라우저가 같은 값으로 쓰게 고정한다.

검증 기준:

- `curl -s localhost:5173/ssr`에 날짜가 `2026년 9월 1일`로 나오고, 게시글 제목 등장 횟수가 2로 돌아온다.
- 브라우저 `/ssr` 콘솔 에러 0.
- 테스트: 실행 환경 로케일·타임존을 바꿔도 같은 문자열.

(결과는 직접 채운다)
